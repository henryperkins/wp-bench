# WS1.1 Loader Canonicalization and Selection v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Resolve exactly one canonical suite, normalize every selected-test descriptor identically from local JSON and Hub/Parquet sources, and replace the PRNG selector with a sealed, order-independent selection plan and selected catalog.

**Architecture:** `datasets.py` becomes the sole normalization boundary and returns a suite-scoped `LoadedSuite`; `verification.py` builds one declared/effective verification contract used by both selection and execution; `selection.py` converts one `LoadedSuite` plus one validated request into one `RunSelection`. `core.py` resolves that object once per invocation and shares it across every mode, model, and skills variant. The exporter preserves raw source context rather than becoming a second canonicalizer.

**Tech Stack:** Python 3.10+, dataclasses, Pydantic v2, Typer, Hugging Face Datasets, PyArrow/Parquet, `orjson`, the WS1.0 RFC 8785 wrapper, `hashlib`, pytest, Ruff, and mypy.

**Spec:** `../specs/2026-08-16-benchmark-integrity-design.md`, especially “Canonical manifest,” “Selection-plan fields and digest preimages,” “Limited selection contract,” “Verification integrity,” and rollout milestone WS1.1. The suite-policy seam is shared with `../specs/2026-08-16-wordpress-coverage-expansion-design.md`.

### Stable loader interfaces

Implement these public shapes in `python/wp_bench/datasets.py`:

```python
CanonicalStratum = Literal[
    "category",
    "difficulty",
    "artifact_kind",
    "runtime_profile",
    "coverage_family",
    "release_focus",
    "wordpress_target_version",
]

DEFAULT_SMOKE_STRATA: tuple[CanonicalStratum, ...] = (
    "category",
    "difficulty",
)

@dataclass(frozen=True)
class SuiteDescriptorPolicy:
    suite_id: str
    suite_content_version: str | None
    execution_schema_version: str
    smoke_strata: tuple[CanonicalStratum, ...]
    release_focus: str | None
    wordpress_target_version: str | None
    suite_manifest_json: dict[str, Any] | None
    suite_manifest_sha256: str | None

@dataclass(frozen=True)
class ExecutionSourceContext:
    policy: SuiteDescriptorPolicy
    source_document_id: str | None
    source_document_metadata: dict[str, Any]
    maintainer_qa_available: bool

@dataclass(frozen=True)
class DatasetRequestIdentity:
    source: Literal["local", "huggingface"]
    name: str
    revision: str | None
    split: str

@dataclass
class ExecutionTest:
    id: str
    suite: str
    prompt: str
    expected_behavior: str
    category: str
    difficulty: str | None
    requirements: list[str]
    test_function: str | None
    static_checks: dict[str, Any]
    runtime_checks: dict[str, Any]
    reference_solution: str | None
    metadata: dict[str, Any]
    artifact_kind: Literal[
        "php_snippet", "wp_plugin_files", "wp_theme_files"
    ] = "php_snippet"
    reference_files: dict[str, str] | None = None
    exploit_solutions: list[str] | None = None
    source_document_id: str | None = None
    source_document_metadata: dict[str, Any] = field(default_factory=dict)
    execution_schema_version: str = "1.0"
    execution: dict[str, Any] = field(default_factory=dict)
    runtime_profile: str | None = None
    coverage_family: str | None = None
    release_focus: str | None = None
    wordpress_target_version: str | None = None

@dataclass(frozen=True)
class LoadedSuite:
    suite_id: str
    dataset_request: DatasetRequestIdentity
    policy: SuiteDescriptorPolicy
    tests: tuple[ExecutionTest, ...]
    maintainer_qa_available: bool

class SuitePolicyResolver(Protocol):
    def __call__(
        self,
        *,
        suite_id: str,
        suite_manifest_json: dict[str, Any],
        suite_manifest_sha256: str | None,
    ) -> SuiteDescriptorPolicy: ...

def normalize_execution_test(
    raw: Mapping[str, object],
    *,
    context: ExecutionSourceContext,
) -> ExecutionTest: ...

def load_suite(
    config: DatasetConfig,
    *,
    suite_id: str,
    policy_resolver: SuitePolicyResolver | None = None,
) -> LoadedSuite: ...
```

`ExecutionTest` remains a compatibility-facing runtime object, but production
code treats normalized instances as read-only. Hashes are computed from fresh
projections at selection seal rather than cached on this mutable dataclass.
WS1.5 later re-hashes before invocation to detect drift.

`DatasetRequestIdentity` copies the four request fields exactly and deliberately
excludes `cache_dir`. It is internal attribution/validation context, not a
canonical dataset identity: it enters no descriptor, selection preimage,
catalog, or contract fingerprint. WS1.3 later resolves immutable source
identity separately.

With no manifest, `load_suite()` creates the built-in schema-1 policy:

```python
SuiteDescriptorPolicy(
    suite_id=suite_id,
    suite_content_version=None,
    execution_schema_version="1.0",
    smoke_strata=("category", "difficulty"),
    release_focus=None,
    wordpress_target_version=None,
    suite_manifest_json=None,
    suite_manifest_sha256=None,
)
```

If local files or Hub rows declare a manifest, `policy_resolver=None` is an
`unsupported_suite_manifest` error. Otherwise `load_suite()` calls the resolver
with the exact keyword names `suite_id=`, `suite_manifest_json=`, and
`suite_manifest_sha256=`, passing the concrete raw object and optional declared
transport digest. It then verifies the returned policy's suite, manifest
object, digest, nonempty manifested content version, and row/document schema
agreement before normalizing tests. This exact injected callable is the
merge-order seam for a future validator; WS1.1 does not inspect workstream
names or raw manifest versions.

### Normalization matrix

| Canonical field | Source and rule |
|---|---|
| `id`, `prompt` | Require nonempty strings and preserve bytes exactly. Duplicate IDs reject the resolved suite. |
| `expected_behavior` | Missing or null becomes the exact empty string; otherwise require a string and preserve it byte-for-byte. |
| `suite` | Requested/resolved suite. Local directory identity or Hub row `suite`; schema-2 `suite_id` may also be present and must equal `suite`. Never a document `id` or Hub repository name. |
| `source_document_id` | Local document `id` or exported audit-only column; absent becomes null. Excluded from every descriptor, digest, and record. |
| `source_document_metadata` | The source execution document's concrete `metadata` object; missing or null becomes an empty object. Preserve it for export/inheritance and legacy adaptation, but exclude it from every descriptor, digest, and record. |
| `execution_schema_version` | Always the validated policy's `execution_schema_version`. A document `schema_version`, when present, must be a string exactly equal to it; omission is allowed only for the built-in schema-1 policy and means `1.0`. A document `version` is content revision only and never supplies or enters this field. |
| `category` | Missing, null, or exact empty string becomes `general`; otherwise preserve the authored nonempty string byte-for-byte. |
| `difficulty` | Missing, null, exact empty string, or exact legacy sentinel `unknown` becomes null; otherwise preserve the authored string. |
| `artifact_kind` | Missing, null, or exact empty string becomes `php_snippet`; values outside the three active contract literals reject. |
| `test_function`, `reference_solution` | Missing, null, or exact empty string becomes null; wrong types reject. |
| `reference_files` | Missing, null, or empty object becomes null; otherwise require `dict[str, str]`. |
| `exploit_solutions` | Local missing/null/empty becomes null; Hub always becomes null because public export omits maintainer QA. |
| `requirements` | Missing becomes an empty list; require an ordered list of strings. |
| `static_checks`, `runtime_checks`, `execution` | Missing becomes an empty object; require concrete JSON objects and preserve nested array order. |
| `runtime_profile` | `execution.profile`; missing, null, or exact empty string becomes null. |
| `coverage_family` | `metadata.coverage.family`; missing, null, or exact empty string becomes null. |
| `release_focus` | First nonempty string from task metadata then validated suite inheritance; missing/null/exact empty becomes null. Schema 2 requires a non-null result. |
| `wordpress_target_version` | First nonempty string from task metadata, validated suite inheritance, then schema-1 execution-document `metadata.wp_version`; missing/null/exact empty becomes null. Preserve versions as strings. Schema 2 requires a non-null result. |
| `metadata` | Missing or null becomes an empty object; otherwise require an object. Preserve task metadata for legacy consumers. Local suite metadata may remain nested under `suite_metadata`, but raw metadata never enters a canonical projection. |

Do not trim or case-fold nonempty authored strings. Do not coerce strings,
floats, booleans, tuples, Arrow scalar/container types, or mapping subclasses
into digest inputs. Decode JSON transport fields into fresh concrete Python
JSON trees and fail malformed or unrepresentable values.

### Stable verification and selection interfaces

Create `python/wp_bench/verification.py`:

```python
VerificationDivergence = Literal[
    "none", "gateway_only", "dimension_skipped"
]

@dataclass(frozen=True)
class VerificationPolicy:
    skip_static: bool
    skip_runtime: bool

@dataclass(frozen=True)
class VerificationContract:
    declared_specification: dict[str, Any]
    effective_specification: dict[str, Any]
    verification_sha256: str
    effective_verification_sha256: str
    divergence: VerificationDivergence

def gateway_name(signature: str | None) -> str | None: ...

def build_verification_contract(
    test: ExecutionTest,
    policy: VerificationPolicy,
) -> VerificationContract: ...
```

`VerificationPolicy` requires concrete booleans and rejects both flags true,
matching the run-config invariant that at least one grading dimension remains.

Both specification objects have exactly these keys:

```python
{
    "execution_schema_version": test.execution_schema_version,
    "execution": test.execution,
    "static_checks": static_checks,
    "runtime_checks": runtime_checks,
}
```

`core.py` passes `effective_specification` to execution; it never rebuilds the
gateway or skip policy independently.

Gateway extraction preserves the current deliberately small grammar: call
`signature.strip()`, match `\A[A-Za-z_][A-Za-z0-9_]*`, and use the leading
match; ignore the remaining model-facing PHP signature text. Null adds no
gateway, while a non-null signature with no match fails preflight. A missing
`runtime_checks.assertions` is the empty authored list; if the key is present,
its value must be a concrete JSON list or preflight fails with the test ID and
`runtime_checks.assertions` field path. Preserve authored list order. Prepend
this exact object to the effective `runtime_checks.assertions`:

```python
{
    "type": "function_exists",
    "target": name,
    "description": f"Defines test function {name}()",
    "weight": 0,
}
```

Replace the legacy selector API with these shapes in `selection.py`:

```python
DEFAULT_SELECTION_SEED = 1337

@dataclass(frozen=True)
class SelectionRequest:
    limit: int | None
    test_ids: tuple[str, ...]
    seed: int | None

@dataclass(frozen=True)
class SelectedRunTest:
    test: ExecutionTest
    catalog_entry: SelectedTest
    verification: VerificationContract

@dataclass(frozen=True)
class RunSelection:
    dataset_request: DatasetRequestIdentity
    suite_policy: SuiteDescriptorPolicy
    maintainer_qa_available: bool
    verification_policy: VerificationPolicy
    plan: SelectionPlan
    selected: tuple[SelectedRunTest, ...]

    @property
    def selected_tests(self) -> tuple[ExecutionTest, ...]: ...

def build_run_selection(
    suite: LoadedSuite,
    request: SelectionRequest,
    *,
    verification_policy: VerificationPolicy,
) -> RunSelection: ...
```

The request rules are exact:

- reject an empty universe, duplicate universe IDs, empty requested-ID tokens,
  unknown IDs, invalid strata, and unsafe integer values; normalize repeated
  requested IDs to their first occurrence after trimming;
- reject `test_ids` combined with `limit` or a non-null seed;
- reject a non-null seed without a limit;
- with `limit` and a null requested seed, consult effective seed `1337`;
- compare the selected ID set to the complete universe to derive effective
  kind, so a limit or explicit list covering the universe is `full`; and
- record the actual path as `full/1`, `explicit-id-set/1`, or
  `stratified-hash-round-robin/2`, even when a requested path is effectively
  full.

## Acceptance and Later-Slice Handoffs

WS1.1 is complete when all of the following are true:

- One resolved suite and one canonical normalization path feed every run.
- Local JSON and real Parquet round-trip sources produce identical benchmark
  catalogs, universe/catalog digests, and per-test digests.
- `stratified-hash-round-robin/2` matches every published vector and is
  independent of source order and Python PRNG/hash behavior.
- Full, limited-smoke, and explicit-smoke classifications are mechanical, and
  conflicting or ignored selector requests fail before execution.
- Every invocation resolves one `RunSelection`; all units share it.
- User-facing subset language says smoke and makes no representativeness claim.
- Complete WS1.0 contract, reader, and immutable-corpus tests exist and pass;
  WS1.1 does not activate against Checkpoint A alone.
- `ruff check python`, `mypy python`, and `pytest python -q` pass.

This directly satisfies benchmark-integrity acceptance criterion 5, the WS1.1
portion of criterion 25, and the dataset/catalog portion of criterion 26. It
provides, but does not finish, these later contracts:

- WS1.2 copies the catalog into a manifest and both sealed
  `verification_sha256` and `effective_verification_sha256` into terminal
  records without recomputation, making the planned denominator recoverable.
- WS1.3 computes dataset snapshots and the complete contract fingerprint, then
  proves the second local/Hub parity gate.
- WS1.4 turns smoke classification and verification divergence into eligibility
  decisions; WS1.1 does not declare leaderboard eligibility.
- WS1.5 performs the pre-invocation verification-drift assertion through the
  coordinator by rebuilding a current candidate with the shared builder and
  comparing it to each retained sealed `VerificationContract`; runners still
  execute only the retained contract.
- The later audit preflight consumes WS1.1's suite-level
  `maintainer_qa_available` signal and fails a Hub-only QA audit instead of
  treating absent public controls as coverage.
- Workstream 3 may supply a validated `SuiteDescriptorPolicy` at any time. Its
  presence activates declared strata/defaults; its branch or milestone name
  never does.
